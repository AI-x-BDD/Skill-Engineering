# Rule 1 - 一份樣板由骨架與範例兩個檔案組成

- Level: `MUST`
- 每一份樣板都必須同時包含「骨架」與「範例」兩個檔案，缺一不可
- 骨架是供 AI 複製後改寫的樣板本體，範例是填寫完成的示範
- 不可只建立骨架而沒有範例，也不可只建立範例而沒有骨架

## Good Example

- `class-diagram` 這份樣板同時有骨架與範例

```text
templates/
├── class-diagram.mmd
└── class-diagram.example.mmd
```

## Bad Example

- 只有骨架，缺少範例，執行該 step 的 AI 無法得知填位符號實際該怎麼填

```text
templates/
└── class-diagram.mmd
```

# Rule 2 - 骨架與範例的路徑與命名

- Level: `MUST`
- 骨架路徑為 `<skill-package>/templates/<樣板名字>.<格式>`
- 範例路徑為 `<skill-package>/templates/<樣板名字>.example.<格式>`
- 兩個檔案放在同一個 `templates/` 目錄，且使用同一個 `<樣板名字>`
- 範例的 `.example` 必須放在樣板名字與副檔名之間

## Good Example

- 骨架與範例同目錄、同樣板名字，範例多一個 `.example`

```text
<skill-package>/templates/class-diagram.mmd
<skill-package>/templates/class-diagram.example.mmd
```

## Bad Example

- 範例放在別的目錄，且用 `-example` 命名，無法由骨架名稱推得範例路徑

```text
<skill-package>/templates/class-diagram.mmd
<skill-package>/examples/class-diagram-example.mmd
```

# Rule 3 - 樣板名字以主題命名

- Level: `MUST`
- 樣板名字以該樣板的主題命名，使用 kebab-case 小寫英文
- 樣板名字不可包含 Phase 或 step 編號

## Good Example

- 以主題命名，SOP 插入新 step 後檔名仍然成立

```text
templates/class-diagram.mmd
templates/class-diagram.example.mmd
```

## Bad Example

- 用編號命名，SOP 插入新 step 後編號改變，檔名就對不上

```text
templates/phase2-step6.mmd
templates/phase2-step6.example.mmd
```

# Rule 4 - 骨架與範例使用相同且真實的副檔名

- Level: `MUST`
- 骨架與範例的 `<格式>` 副檔名必須相同
- 副檔名必須是產出檔案的真實格式，例如 Mermaid 用 `.mmd`、Markdown 用 `.md`、JSON 用 `.json`

## Good Example

- 兩個檔案副檔名相同，且都是 Mermaid 的真實格式

```text
templates/class-diagram.mmd
templates/class-diagram.example.mmd
```

## Bad Example

- 範例改用 `.md`，與骨架副檔名不同，也不是產出檔案的真實格式

```text
templates/class-diagram.mmd
templates/class-diagram.example.md
```
