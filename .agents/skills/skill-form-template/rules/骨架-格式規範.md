# Rule 1 - 骨架整個檔案內容就是樣板本體

- Level: `MUST`
- 骨架檔的整個內容就是樣板本體，AI 會直接複製整份骨架再改寫
- 不可夾帶說明文字、規則或給 AI 的指示
- 需要說明的事，交給 SOP 的 step、RuleFile 或範例，不寫進骨架

## Good Example

- 整個檔案只有樣板本體

```text
classDiagram
    class {{類別名稱}} {
        <<{{new 或 modified}}>>
        +{{方法名稱}}({{參數名稱}}) {{回傳型別}}
    }
```

## Bad Example

- 第一行是給 AI 的指示，AI 複製骨架後這行會混進產出檔案

```text
請依下列格式輸出類別圖，modified 的類別只列出變動的成員：
classDiagram
    class {{類別名稱}} {
        <<{{new 或 modified}}>>
        +{{方法名稱}}({{參數名稱}}) {{回傳型別}}
    }
```

# Rule 2 - 同一份骨架只使用一種填位符號格式

- Level: `MUST`
- 同一份骨架內的所有填位符號，必須使用同一種格式
- 填位符號必須能被一眼辨識，與樣板的固定內容區分開來

## Good Example

- 所有填位符號都是 `{{名稱}}`

```text
classDiagram
    class {{類別名稱}} {
        -{{屬性名稱}}: {{屬性型別}}
    }
```

## Bad Example

- 同一份骨架混用 `{{ }}`、`<>` 與 `[ ]` 三種填位符號格式

```text
classDiagram
    class {{類別名稱}} {
        -<屬性名稱>: [屬性型別]
    }
```

# Rule 3 - 填位符號預設使用 `{{名稱}}`

- Level: `SHOULD`
- 填位符號預設格式為 `{{名稱}}`
- 若 `{{名稱}}` 與該檔案格式本身的語法衝突，可以改用其他格式，例如 `[[名稱]]`
- 改用其他格式後，仍須符合 Rule 2，整份骨架統一使用該格式

## Good Example

- 檔案格式本身使用 `{{ }}` 語法，骨架改用 `[[名稱]]` 作為填位符號，兩者不會混淆

```text
<h1>[[頁面標題]]</h1>
<p>{{ site.name }}</p>
```

## Bad Example

- 檔案格式本身使用 `{{ }}` 語法，填位符號卻也用 `{{ }}`，分不出哪個是要改寫的填位符號

```text
<h1>{{頁面標題}}</h1>
<p>{{ site.name }}</p>
```

# Rule 4 - 填位符號名稱要能自我說明

- Level: `SHOULD`
- 填位符號名稱必須讓人與 AI 一看就知道要填什麼
- 因為骨架內不能另外放說明，填位符號名稱就是唯一的提示
- 不使用 `{{x}}`、`{{1}}`、`{{foo}}` 這類沒有意義的名稱

## Good Example

- 名稱直接說出要填的內容

```text
class {{類別名稱}} {
    +{{方法名稱}}({{參數名稱}}) {{回傳型別}}
}
```

## Bad Example

- 名稱沒有意義，AI 無法判斷該填什麼

```text
class {{x}} {
    +{{y}}({{z}}) {{w}}
}
```

# Rule 5 - 重複區塊在骨架中只放一個實例

- Level: `MUST`
- 重複出現的區塊，骨架中只放一個實例
- 不用註解或標記來說明哪個區塊要重複
- 重複的寫法由範例示範

## Good Example

- 類別區塊只放一個實例

```text
classDiagram
    class {{類別名稱}} {
        +{{方法名稱}}() {{回傳型別}}
    }
```

## Bad Example

- 放了兩個實例，還用註解說明要重複，註解會混進產出檔案

```text
classDiagram
    %% 以下區塊每個類別重複一次
    class {{類別名稱1}} {
        +{{方法名稱1}}() {{回傳型別1}}
    }
    class {{類別名稱2}} {
        +{{方法名稱2}}() {{回傳型別2}}
    }
```

# Rule 6 - 骨架的固定部分必須符合檔案格式的語法

- Level: `SHOULD`
- 骨架去掉填位符號後留下的固定部分，應符合該檔案格式的語法
- 固定部分包含宣告行、關鍵字、括號與縮排

## Good Example

- 固定部分有 `classDiagram` 宣告行，大括號成對

```text
classDiagram
    class {{類別名稱}} {
        +{{方法名稱}}() {{回傳型別}}
    }
```

## Bad Example

- 固定部分缺少 `classDiagram` 宣告行，大括號也沒有成對，AI 複製後會得到無法解析的檔案

```text
    class {{類別名稱}} {
        +{{方法名稱}}() {{回傳型別}}
```
