# SOP

## Phase 1 -- 讀取目標

1. READ 讀取 `rules/腳本組成-格式規範.md`，將其視為唯一腳本組成規範來源。
2. READ 依腳本組成規範，讀取目標腳本的既有內容（尚未建立者視為新增），確認要新增、修改或重寫的腳本範圍。

## Phase 2 -- 完成腳本

1. READ 讀取 `rules/介面-格式規範.md`，將其視為唯一腳本介面規範來源。
2. THINK 依腳本組成規範與腳本介面規範，決定腳本的職責、參數、輸出與退出碼。
3. READ 讀取 `rules/相依套件-格式規範.md`，將其視為唯一相依套件規範來源。
4. THINK 依相依套件規範，決定是否需要第三方套件，並整理 PEP 723 區塊內容。
5. READ 讀取 `rules/跨平臺-格式規範.md`，將其視為唯一跨平臺規範來源。
6. WRITE 依腳本組成規範、跨平臺規範與前述思考結果，撰寫或修改目標腳本。

## Phase 3 -- 完成執行規範與驗證

1. READ 讀取 `rules/腳本執行-格式規範.md`，將其視為唯一腳本執行規範來源。
2. DELEGATE 依腳本執行規範執行目標腳本的 `--help`，取回退出碼以確認腳本能啟動；失敗時回到 Phase 2 第 6 步修正。
3. WRITE 目標 skill 的 `rules/` 尚無腳本執行規範時，將其原樣複製過去。
4. READ 依腳本組成規範、腳本介面規範、相依套件規範、跨平臺規範與腳本執行規範回頭核對腳本；若不符合，立即修正。
