# Rule 1 - 每支腳本的開頭都要有 PEP 723 區塊

- Level: `MUST`
- 每支腳本的開頭都要有 PEP 723 `script` 區塊，由 `# /// script` 開始、`# ///` 結束
- 區塊內必須有 `requires-python` 與 `dependencies`；`requires-python` 預設寫 `">=3.11"`
- 腳本只使用 `requires-python` 下限版本已有的語法與標準庫
- 沒有第三方套件時，`dependencies` 寫 `[]`，不省略區塊；沒有區塊的腳本在有 `pyproject.toml` 的目錄下用 `uv run` 執行時，uv 會先安裝那個專案，有區塊則不受影響
- 套件清單只寫在這個區塊，不另外放 `requirements.txt` 或 `pyproject.toml`

## Good Example

- 沒有第三方套件，仍然寫出區塊，`dependencies` 為空清單

```python
# /// script
# requires-python = ">=3.11"
# dependencies = []
# ///
"""檢查 RuleFile 的 Rule 編號是否連續。"""
```

## Bad Example

- 沒有區塊，套件與 Python 版本的需求沒有任何宣告

```python
"""檢查 RuleFile 的 Rule 編號是否連續。"""
import yaml
```

- 套件清單放在腳本以外的檔案，與腳本分家後容易漂移

```text
scripts/
├── check_rulefile.py
└── requirements.txt
```

# Rule 2 - 預設只用標準庫

- Level: `SHOULD`
- 能用標準庫完成的事，不引入第三方套件
- 必須引入第三方套件時，在思考結果中說明標準庫為什麼不夠用
- 只用標準庫的腳本不需要安裝任何東西，在只有 Python 的機器上也能直接執行

## Good Example

- 解析參數、處理 JSON 與路徑都用標準庫完成

```python
import argparse
import json
from pathlib import Path
```

## Bad Example

- 只是要讀一個 JSON 檔並印出摘要，卻引入 `pandas` 與 `rich`

```python
# /// script
# requires-python = ">=3.11"
# dependencies = ["pandas>=2,<3", "rich>=13,<14"]
# ///
```

# Rule 3 - 以 PyPI 名稱宣告，且與實際 import 一致

- Level: `MUST`
- `dependencies` 填的是 PyPI 上的套件名稱，不是 `import` 用的模組名稱，例如 `import yaml` 對應 `"pyyaml"`
- 腳本實際 import 的每一個第三方套件，都要列在 `dependencies`；`dependencies` 也不可列出沒有用到的套件
- 標準庫的模組不列入 `dependencies`

## Good Example

- 宣告 `pyyaml`，程式裡 `import yaml`

```python
# dependencies = ["pyyaml>=6,<7"]
import yaml
```

## Bad Example

- 宣告成 import 的模組名稱 `yaml`，PyPI 上的套件名稱是 `pyyaml`；兩者不同時，會找不到套件或裝到另一個套件

```python
# dependencies = ["yaml>=6,<7"]
import yaml
```

- `requests` 沒有宣告，`json` 是標準庫卻被列入

```python
# dependencies = ["json"]
import json
import requests
```

# Rule 4 - 第三方套件寫版本範圍

- Level: `SHOULD`
- 每個第三方套件都寫版本範圍，使用 PEP 508 的版本規格，例如 `"pyyaml>=6,<7"`
- 範圍的上限擋在下一個主版本，避免套件改版後改了 API，讓腳本壞掉

## Good Example

- 下限是已測試過的版本，上限擋在下一個主版本

```python
# dependencies = ["pyyaml>=6,<7", "requests>=2.31,<3"]
```

## Bad Example

- 沒有版本範圍，套件出新的主版本時，腳本可能在沒有任何修改的情況下壞掉

```python
# dependencies = ["pyyaml", "requests"]
```

# Rule 5 - 有第三方套件的腳本要有缺套件提示

- Level: `MUST`
- `dependencies` 不是空清單的腳本，要用 `try/except ModuleNotFoundError` 包住第三方套件的 import
- 缺套件時向 stderr 輸出提示：缺少哪個套件、改用 `uv run <腳本路徑>` 執行、不要用 `pip` 安裝到系統 Python
- 提示之後以退出碼 2 結束；不使用 `sys.exit("訊息")`，它的退出碼是 1
- `dependencies` 是空清單的腳本不需要這段提示

## Good Example

- 提示改用 `uv run`，並以 2 結束

```python
import sys
from pathlib import Path

try:
    import yaml
except ModuleNotFoundError as e:
    print(
        f"[無法執行] 缺少套件 {e.name}。請改用 `uv run {Path(__file__).as_posix()}` 執行；"
        "套件已宣告在本檔開頭的 PEP 723 區塊，不要用 pip 安裝到系統 Python。",
        file=sys.stderr,
    )
    sys.exit(2)
```

## Bad Example

- 缺套件時只有 `ModuleNotFoundError: No module named 'yaml'`，AI 只能自己猜著 `pip install`

```python
import yaml
```

- 用 `sys.exit("訊息")`，退出碼是 1，與「發現問題」無法區分，也沒有說明該怎麼處理

```python
try:
    import yaml
except ModuleNotFoundError as e:
    sys.exit(f"缺少套件 {e.name}")
```

# Rule 6 - 腳本不得自行安裝套件或下載程式碼

- Level: `MUST`
- 腳本內不可呼叫 `pip install`、`uv pip install`，也不可用 `subprocess` 安裝任何套件
- 腳本不可下載並執行遠端程式碼，也不可下載沒有宣告的可執行檔
- 套件一律寫在 `dependencies`，交給 `uv run` 處理

## Good Example

- 缺套件時只提示，不自己安裝

```python
try:
    import yaml
except ModuleNotFoundError as e:
    print(f"[無法執行] 缺少套件 {e.name}，請改用 uv run 執行", file=sys.stderr)
    sys.exit(2)
```

## Bad Example

- 腳本自己呼叫 pip，在使用者不知情下改動環境

```python
subprocess.run([sys.executable, "-m", "pip", "install", "pyyaml"], check=True)
```
