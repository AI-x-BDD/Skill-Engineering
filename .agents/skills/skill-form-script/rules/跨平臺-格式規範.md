# Rule 1 - 讀寫檔案一律明確指定編碼

- Level: `MUST`
- `open()`、`Path.read_text()`、`Path.write_text()` 一律明確傳入 `encoding`，不依賴系統預設編碼
- 讀取使用者提供或其他工具產生的文字檔，用 `encoding="utf-8-sig"`，同時接受有 BOM 與沒有 BOM 的 UTF-8
- 腳本自己寫出的文字檔，用 `encoding="utf-8"`，不加 BOM
- Windows 的預設編碼是系統地區編碼（繁體中文 Windows 為 cp950），讀取 UTF-8 檔案會出現 `UnicodeDecodeError` 或亂碼；Python 3.15 才會把預設改為 UTF-8
- Windows PowerShell 5.1 的 `Set-Content -Encoding UTF8` 與部分編輯器存檔會加上 BOM；用 `utf-8` 讀取時，BOM 會變成第一個字元 `﻿`，第一行的標題或欄位會被漏掉
- 二進位檔案用 `"rb"`、`"wb"` 讀寫，不指定 `encoding`

## Good Example

- 讀取外部檔案用 `utf-8-sig`，寫出檔案用 `utf-8`，在任何平臺上結果都相同

```python
text = Path(args.errorfile).read_text(encoding="utf-8-sig")
Path(args.output).write_text(report, encoding="utf-8", newline="\n")
```

## Bad Example

- 沒有指定編碼；在繁體中文 Windows 上讀取 UTF-8 的 `SKILL.md`，會拋出 `UnicodeDecodeError: 'cp950' codec can't decode byte 0xe7`

```python
text = open(args.rulefile).read()
```

- 讀取外部檔案用 `utf-8`；有 BOM 的檔案第一行會變成 `﻿## E1001 - 找不到訂單`，第一個錯誤碼被漏掉，檢查卻仍然通過

```python
text = Path(args.errorfile).read_text(encoding="utf-8")
```

# Rule 2 - 啟動時把 stdout 與 stderr 設成 UTF-8

- Level: `MUST`
- `main()` 一開始就把 `sys.stdout` 與 `sys.stderr` 重設為 UTF-8
- 輸出 JSON 時使用 `ensure_ascii=False`，讓中文維持可讀
- 輸出被導向管線或檔案時，Python 會使用系統編碼；遇到系統編碼無法表示的字元，`print` 會拋出 `UnicodeEncodeError`

## Good Example

- 先重設編碼，再輸出含中文與符號的 JSON

```python
def main() -> int:
    sys.stdout.reconfigure(encoding="utf-8")
    sys.stderr.reconfigure(encoding="utf-8")
    print(json.dumps({"summary": "✓ 通過"}, ensure_ascii=False))
    return 0
```

## Bad Example

- 沒有重設編碼；在 cp950 的系統上輸出被導向管線時，`✓` 無法編碼，拋出 `UnicodeEncodeError: 'cp950' codec can't encode character '\u2713'`

```python
def main() -> int:
    print("✓ 通過")
    return 0
```

# Rule 3 - 路徑用 `pathlib`，目標路徑由參數傳入

- Level: `MUST`
- 路徑一律用 `pathlib.Path` 組合，不手寫 `\` 或 `/` 拼接字串，也不寫死磁碟代號
- 腳本不假設目前工作目錄；要處理的目標路徑由命令列參數傳入
- 腳本自己旁邊的資源，用 `Path(__file__).resolve().parent` 定位
- 輸出給 AI 的路徑使用 `Path.as_posix()`，統一為正斜線

## Good Example

- 目標路徑來自參數，自身位置用 `__file__` 定位，輸出用正斜線

```python
target = Path(args.target)
skill_dir = Path(__file__).resolve().parent.parent
rules = sorted((skill_dir / "rules").glob("*.md"))
print(json.dumps({"rules": [p.as_posix() for p in rules]}, ensure_ascii=False))
```

## Bad Example

- 手寫反斜線、依賴目前工作目錄；換平臺或換工作目錄就找不到檔案

```python
rules = glob.glob(os.getcwd() + "\\rules\\*.md")
```

# Rule 4 - 不呼叫 shell 與平臺專屬指令

- Level: `MUST`
- 不使用 `os.system()`，也不使用 `subprocess` 的 `shell=True`
- 不呼叫平臺專屬的指令，例如 `ls`、`cp`、`rm`、`grep`、`sed`、`chmod`、`del`、`copy`；檔案操作用 `pathlib` 與 `shutil`，文字處理用 Python
- 必須呼叫外部程式時，用 `subprocess.run([...])` 的清單形式，並先用 `shutil.which()` 確認程式存在

## Good Example

- 先確認程式存在，再用清單形式呼叫

```python
git = shutil.which("git")
if git is None:
    print("[無法執行] 找不到 git，請先安裝 git", file=sys.stderr)
    sys.exit(2)
subprocess.run([git, "status", "--short"], check=False)
```

## Bad Example

- Windows 沒有 `rm`、`cp`，shell 語法也因平臺而異

```python
os.system("rm -rf build && cp -r src build")
```

# Rule 5 - 不依賴 shebang 與執行權限

- Level: `MUST`
- 腳本不靠 shebang（`#!`）與 `chmod +x` 來執行；Windows 不會解讀 shebang
- 腳本由 `uv run <腳本路徑>` 啟動，不需要 shebang

## Good Example

- 檔案以 PEP 723 區塊開頭，沒有 shebang

```python
# /// script
# requires-python = ">=3.11"
# dependencies = []
# ///
```

## Bad Example

- 用 shebang 指定 uv，只有 macOS 與 Linux 有效，Windows 上不會被執行

```python
#!/usr/bin/env -S uv run --script
```

# Rule 6 - 暫存檔用 `tempfile`，輸出換行固定為 `\n`

- Level: `SHOULD`
- 暫存檔與暫存目錄用 `tempfile` 建立，不寫死 `/tmp` 或 `C:\Temp`
- 寫出文字檔時固定傳入 `newline="\n"`，避免在 Windows 上寫成 CRLF，讓版本控制出現整檔差異

## Good Example

- 暫存目錄由 `tempfile` 建立，換行固定為 `\n`

```python
with tempfile.TemporaryDirectory() as tmp:
    out = Path(tmp) / "report.md"
    out.write_text(content, encoding="utf-8", newline="\n")
```

## Bad Example

- `/tmp` 在 Windows 不存在；預設換行在 Windows 會寫成 CRLF

```python
out = Path("/tmp/report.md")
out.write_text(content, encoding="utf-8")
```
