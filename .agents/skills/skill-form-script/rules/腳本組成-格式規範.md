# Rule 1 - 腳本只使用 Python，且放在 `scripts/` 底下

- Level: `MUST`
- 腳本一律是 Python 檔，副檔名為 `.py`
- 腳本放在目標 skill 的 `scripts/` 目錄，路徑為 `<skill-package>/scripts/<腳本名字>.py`
- 不使用 Shell script 或其他語言撰寫腳本，例如 `.sh`、`.ps1`、`.bat`、`.js`

## Good Example

- 腳本是 `scripts/` 底下的 `.py` 檔

```text
skill-api-doc/
├── SKILL.md
└── scripts/
    └── check_error_codes.py
```

## Bad Example

- 用 Shell script 撰寫，Windows 上無法直接執行，也不在支援的語言範圍內

```text
skill-api-doc/
├── SKILL.md
└── scripts/
    └── check-error-codes.sh
```

# Rule 2 - 一支腳本就是一個獨立的單檔

- Level: `MUST`
- 一支腳本只有一個 `.py` 檔，不拆成多個模組
- 不為腳本建立專案檔，例如 `pyproject.toml`、`requirements.txt`、`setup.py`、`__init__.py`、虛擬環境、lock 檔
- 腳本之間不互相 import；兩支腳本需要相同的邏輯時，各自保留一份

## Good Example

- 每支腳本各自獨立，旁邊沒有任何專案檔

```text
scripts/
├── check_error_codes.py
└── list_endpoints.py
```

## Bad Example

- 另建專案檔與共用模組，腳本變成一個要維護的 Python 專案

```text
scripts/
├── pyproject.toml
├── requirements.txt
├── common/
│   ├── __init__.py
│   └── io_utils.py
└── check_error_codes.py
```

# Rule 3 - 腳本命名

- Level: `MUST`
- 腳本名字以該腳本的職責命名，使用 snake_case 小寫英文
- 腳本名字不可包含 Phase 或 step 編號
- 腳本名字不可與 Python 標準庫的模組同名，例如 `json.py`、`csv.py`、`random.py`；腳本所在的目錄會排在模組搜尋路徑的最前面，同名會蓋掉標準庫

## Good Example

- 以職責命名，SOP 插入新 step 後檔名仍然成立，也不會蓋掉標準庫

```text
scripts/check_error_codes.py
```

## Bad Example

- 用編號命名，SOP 插入新 step 後編號改變，檔名就對不上

```text
scripts/phase2_step3.py
```

- 與標準庫的 `json` 同名，腳本裡的 `import json` 會載入腳本自己

```text
scripts/json.py
```
