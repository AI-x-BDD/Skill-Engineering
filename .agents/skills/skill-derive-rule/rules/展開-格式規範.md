# Rule 1 - 展開單位

- Level: `MUST`
- 每次展開只處理使用者指定的一個 step
- 每個被展開的 step 對應一份 step 級 RuleFile

## Good Example

- 使用者指定 Phase 3 第 2 步，只為它建立一份 RuleFile

```text
rules/
├── 類別圖-格式規範.md
└── 實作-格式規範.md
```

## Bad Example

- 使用者只指定 Phase 3 第 2 步，卻順便替其他 step 也建立 RuleFile

```text
rules/
├── 類別圖-格式規範.md
├── 實作-格式規範.md
└── 類別圖提案-格式規範.md
```

# Rule 2 - 插入載入 step

- Level: `MUST`
- 在被展開 step 的正前方插入一個 `READ` step，載入新的 step 級 RuleFile
- 該 `READ` step 寫出完整路徑，並寫明「將其視為唯一 <規範名稱> 規範來源」
- 同一 phase 中位於其後的 step 編號依序遞增

## Good Example

- Before

```md
## Phase 3 -- 依類別圖完成開發

1. THINK 依類別圖規範排出開發順序。
2. WRITE 依該順序逐一實作類別圖中的類別。
```

- After：在第 2 步前插入載入 step，原第 2 步變成第 3 步

```md
## Phase 3 -- 依類別圖完成開發

1. THINK 依類別圖規範排出開發順序。
2. READ 讀取 `rules/實作-格式規範.md`，將其視為唯一實作規範來源。
3. WRITE 依實作規範，按該順序逐一實作類別圖中的類別。
```

## Bad Example

- 載入 step 放到 Phase 1，失去按需載入的效果

```md
## Phase 1 -- 載入規則與需求

1. READ 讀取 `rules/類別圖-格式規範.md`，將其視為唯一類別圖規範來源。
2. READ 讀取 `rules/實作-格式規範.md`，將其視為唯一實作規範來源。
```

# Rule 3 - 改寫被展開的 step

- Level: `MUST`
- 被展開的 step 改寫為「依 <規範名稱> 規範」執行
- 被展開的 step 不寫 RuleFile 路徑，也不重述規則內容

## Good Example

```md
3. WRITE 依實作規範，按該順序逐一實作類別圖中的類別。
```

## Bad Example

- 重複寫出路徑，並把規則內容塞回 step

```md
3. WRITE 依 `rules/實作-格式規範.md` 先寫測試再實作，按該順序逐一實作類別圖中的類別。
```

# Rule 4 - 更新既有的規範引用

- Level: `MUST`
- 展開後 skill 有多份 RuleFile，SOP 中原本只寫「依規範」的 step 必須改為指明規範名稱
- 全域 RuleFile 的 `READ` step 若沒有寫明規範名稱，必須補上「將其視為唯一 <規範名稱> 規範來源」

## Good Example

- Before：skill 只有一份 RuleFile，只寫「依規範」

```md
1. READ 讀取 `rules/類別圖-格式規範.md`，將其視為唯一類別圖與開發規範來源。
2. WRITE 依規範產出類別圖提案並呈現給使用者。
```

- After：指明是類別圖規範

```md
1. READ 讀取 `rules/類別圖-格式規範.md`，將其視為唯一類別圖規範來源。
2. WRITE 依類別圖規範產出類別圖提案並呈現給使用者。
```

## Bad Example

- 已經有兩份 RuleFile，仍只寫「依規範」，無法判斷依據哪一份

```md
2. WRITE 依規範產出類別圖提案並呈現給使用者。
```
