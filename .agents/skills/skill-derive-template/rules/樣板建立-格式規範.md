# Rule 1 - 樣板命名

- Level: `MUST`
- 樣板名字以該 step 把關的主題命名，使用 kebab-case 小寫英文
- 樣板名字不可包含 Phase 或 step 編號
- 骨架與範例使用同一個樣板名字

## Good Example

- 以主題命名，骨架與範例同名，SOP 插入新 step 後檔名仍然成立

```text
templates/class-diagram.mmd
templates/class-diagram.example.mmd
```

## Bad Example

- 用編號命名，SOP 插入新 step 後編號改變，檔名就對不上

```text
templates/phase2-step6.mmd
templates/phase2-step6.example.mmd
```

# Rule 2 - 委派的交付清單必須完整

- Level: `MUST`
- 委派 /skill-form-template 時，交付內容必須包含：目標 skill、樣板名稱與格式（副檔名）、骨架與範例兩個完整路徑、使用者的格式需求、填位符號偏好
- 使用者沒有填位符號偏好時，必須明寫「無偏好」
- 使用者提供現成範本時，必須逐字附上原文，不可只寫主題名
- 缺任一項不得委派

## Good Example

- 五項都齊全，現成範本附上原文

````md
- 目標 skill：plan-with-class-diagram
- 樣板名稱與格式：class-diagram，`.mmd`
- 骨架與範例路徑：`templates/class-diagram.mmd`、`templates/class-diagram.example.mmd`
- 使用者的格式需求：每個類別都標 `<<new>>` 或 `<<modified>>`；現成範本如下
  ```mermaid
  classDiagram
      class CouponService {
          <<new>>
          +apply(order: Order) Money
      }
  ```
- 填位符號偏好：無偏好
````

## Bad Example

- 缺範例路徑與填位符號偏好；現成範本只寫主題名，沒有原文

```md
- 目標 skill：plan-with-class-diagram
- 樣板名稱與格式：class-diagram，`.mmd`
- 骨架路徑：`templates/class-diagram.mmd`
- 使用者的格式需求：依使用者提供的類別圖範本
```

# Rule 3 - 取回後必須核對檔案

- Level: `MUST`
- 取回後必須核對骨架與範例兩個檔案都已存在
- 取回後必須核對路徑、樣板名字、`.example` 的位置與副檔名都正確，也就是骨架為 `<樣板名字>.<格式>`、範例為 `<樣板名字>.example.<格式>`
- 有落差時退回補正，不進入下一步

## Good Example

- 兩個檔案都存在，範例的 `.example` 位於名字與副檔名之間，副檔名相同

```text
templates/class-diagram.mmd           → 存在
templates/class-diagram.example.mmd   → 存在
```

## Bad Example

- 範例的副檔名與骨架不同，卻直接進入下一步

```text
templates/class-diagram.mmd           → 存在
templates/class-diagram.example.md    → 副檔名與骨架不同
```

# Rule 4 - 取回後必須核對內容

- Level: `MUST`
- 取回後必須核對骨架的每個填位符號，在範例中都有對應的填寫
- 取回後必須核對範例中沒有殘留填位符號
- 取回後必須核對使用者的格式需求都已涵蓋
- 有落差時退回補正，不進入下一步

## Good Example

- 骨架的三個填位符號在範例中都已填寫，沒有殘留

```text
骨架：{{類別名稱}}、{{方法名稱}}、{{回傳型別}}
範例：CouponService、apply、Money
範例中殘留的填位符號：無
```

## Bad Example

- 範例殘留 `{{回傳型別}}`，卻直接進入下一步

```text
骨架：{{類別名稱}}、{{方法名稱}}、{{回傳型別}}
範例：CouponService、apply、{{回傳型別}}
```
