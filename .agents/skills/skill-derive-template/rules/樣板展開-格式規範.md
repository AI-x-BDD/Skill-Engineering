# Rule 1 - 展開單位

- Level: `MUST`
- 每次展開只處理使用者指定的一個 step
- 每個被展開的 step 對應一份樣板，也就是骨架與範例兩個檔案

## Good Example

- 使用者指定 Phase 2 第 6 步，只為它建立一份樣板（骨架加範例）

```text
templates/
├── class-diagram.mmd
└── class-diagram.example.mmd
```

## Bad Example

- 使用者只指定一個 step，卻順便替其他 step 也建立樣板

```text
templates/
├── class-diagram.mmd
├── class-diagram.example.mmd
├── dev-order.md
└── dev-order.example.md
```

# Rule 2 - 插入載入 step

- Level: `MUST`
- 在被展開 step 的正前方插入一個 `READ` step，載入新的樣板
- 該 `READ` step 必須同時寫出骨架與範例兩個完整路徑，並分別標註（骨架）、（範例）
- 該 `READ` step 必須寫明兩個檔案都必須讀取，並寫明「將其視為唯一 <樣板名稱> 樣板來源」
- 只寫骨架路徑、漏掉範例路徑屬於錯誤
- 同一 phase 中位於其後的 step 編號依序遞增

## Good Example

- Before

```md
## Phase 2 -- 完成類別圖提案

1. THINK 依需求設計本次要新增或修改的類別。
2. WRITE 輸出類別圖。
```

- After：在第 2 步前插入載入 step，兩個路徑齊全，原第 2 步變成第 3 步

```md
## Phase 2 -- 完成類別圖提案

1. THINK 依需求設計本次要新增或修改的類別。
2. READ 讀取 `templates/class-diagram.mmd`（骨架）與 `templates/class-diagram.example.mmd`（範例），兩個檔案都必須讀取，將其視為唯一類別圖樣板來源。
3. WRITE 輸出類別圖。
```

## Bad Example

- 只寫骨架路徑，執行該 step 的 AI 不知道範例存在，就不會去讀範例

```md
2. READ 讀取 `templates/class-diagram.mmd`，將其視為唯一類別圖樣板來源。
```

- 載入 step 放到 Phase 1，失去按需載入的效果

```md
## Phase 1 -- 載入需求

1. READ 讀取 `templates/class-diagram.mmd`（骨架）與 `templates/class-diagram.example.mmd`（範例），兩個檔案都必須讀取，將其視為唯一類別圖樣板來源。
```

# Rule 3 - 改寫被展開的 step

- Level: `MUST`
- 被展開的 step 改寫為「依 <樣板名稱> 樣板，複製骨架並參照範例填寫，<原本的產出動作>」
- 被展開的 step 不寫樣板路徑，也不重述樣板內容

## Good Example

```md
3. WRITE 依類別圖樣板，複製骨架並參照範例填寫，輸出類別圖。
```

## Bad Example

- 重複寫出路徑，並把樣板內容塞回 step

```md
3. WRITE 依 `templates/class-diagram.mmd` 以 `classDiagram` 開頭，每個類別標 `<<new>>` 或 `<<modified>>`，輸出類別圖。
```

# Rule 4 - 路徑只在第一次 READ 寫出

- Level: `MUST`
- 多個 step 共用同一份樣板時，只有第一次載入的 `READ` step 寫出骨架與範例兩個路徑
- 後續 step 以樣板名稱指明依據，不再寫路徑

## Good Example

- 路徑只出現一次，後續 step 以「類別圖樣板」稱呼

```md
2. READ 讀取 `templates/class-diagram.mmd`（骨架）與 `templates/class-diagram.example.mmd`（範例），兩個檔案都必須讀取，將其視為唯一類別圖樣板來源。
3. WRITE 依類別圖樣板，複製骨架並參照範例填寫，輸出類別圖。
4. WRITE 使用者要求調整時，依類別圖樣板修改類別圖。
```

## Bad Example

- 後續 step 又寫了一次路徑

```md
4. WRITE 使用者要求調整時，依 `templates/class-diagram.mmd` 與 `templates/class-diagram.example.mmd` 修改類別圖。
```

# Rule 5 - 更新既有的引用

- Level: `MUST`
- 展開後 skill 同時有 `rules/` 與 `templates/` 時，SOP 中原本只寫「依規範」的 step，必須改為指明是哪一份規範或哪一份樣板
- 既有的 `READ` step 若沒有寫明規範名稱，必須補上「將其視為唯一 <規範名稱> 規範來源」

## Good Example

- Before：skill 只有一份 RuleFile，只寫「依規範」

```md
1. READ 讀取 `rules/類別圖-格式規範.md`，將其視為唯一規範來源。
2. WRITE 依規範輸出類別圖。
```

- After：樣板展開後，既有的 step 指明是類別圖規範，樣板的 step 指明是類別圖樣板

```md
1. READ 讀取 `rules/類別圖-格式規範.md`，將其視為唯一類別圖規範來源。
2. READ 讀取 `templates/class-diagram.mmd`（骨架）與 `templates/class-diagram.example.mmd`（範例），兩個檔案都必須讀取，將其視為唯一類別圖樣板來源。
3. WRITE 依類別圖規範與類別圖樣板，複製骨架並參照範例填寫，輸出類別圖。
```

## Bad Example

- 已經有 RuleFile 與樣板，仍只寫「依規範」，無法判斷依據哪一份

```md
3. WRITE 依規範輸出類別圖。
```
