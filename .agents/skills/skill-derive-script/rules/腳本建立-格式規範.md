# Rule 1 - 委派的交付清單必須完整

- Level: `MUST`
- 委派 /skill-form-script 時，交付內容必須包含：目標 skill、腳本檔名、改寫前該 step 的原文、腳本職責（輸入、輸出、退出碼語意）、第三方套件與理由、驗收案例（至少一個正例與一個反例）
- 改寫前該 step 的原文必須逐字寫出，不可只寫主題名
- 沒有第三方套件時，必須明寫「無，僅用標準庫」
- 缺任一項不得委派

## Good Example

- 六項都齊全，step 原文逐字附上

```md
- 目標 skill：skill-api-doc
- 腳本檔名：`scripts/check_error_codes.py`
- 改寫前的 step 原文：`3. READ 逐條對照錯誤碼文件，確認每個錯誤碼都有 HTTP 狀態與重試建議。`
- 腳本職責：輸入錯誤碼文件路徑；輸出缺漏清單（JSON，寫在 stdout）；退出碼 0 通過、1 有缺漏、2 無法執行
- 第三方套件：無，僅用標準庫
- 驗收案例：正例 `errors.ok.md` 預期退出碼 0；反例 `errors.bad.md`（缺少重試建議）預期退出碼 1，清單指出缺漏的錯誤碼
```

## Bad Example

- 缺驗收案例；step 原文只寫主題名；沒有說明第三方套件

```md
- 目標 skill：skill-api-doc
- 腳本檔名：`scripts/check_error_codes.py`
- 改寫前的 step 原文：錯誤碼檢查
- 腳本職責：檢查錯誤碼文件
```

# Rule 2 - 取回後必須核對檔案

- Level: `MUST`
- 取回後必須核對腳本檔案已存在，路徑與檔名和交付清單一致
- 取回後必須核對腳本開頭有 PEP 723 區塊，且 `dependencies` 與交付清單的第三方套件一致
- 取回後必須核對目標 skill 的 `rules/` 已有腳本執行規範
- 有落差時退回補正，不進入下一步

## Good Example

- 三項核對都符合

```text
scripts/check_error_codes.py          → 存在，與交付清單一致
PEP 723 dependencies                  → []，與「無，僅用標準庫」一致
rules/腳本執行-格式規範.md             → 已就位
```

## Bad Example

- 目標 skill 沒有腳本執行規範，卻直接進入下一步

```text
scripts/check_error_codes.py          → 存在，與交付清單一致
PEP 723 dependencies                  → []，與「無，僅用標準庫」一致
rules/腳本執行-格式規範.md             → 不存在
```

# Rule 3 - 取回後必須實際執行驗收案例

- Level: `MUST`
- 必須依腳本執行規範實際執行腳本，不可只靠閱讀原始碼判斷
- 至少執行三項：`--help` 的退出碼為 0；正例的退出碼為 0，且輸出符合預期；反例的退出碼與輸出符合預期（檢查類腳本為 1，清單指出預期的問題；輸入無效時為 2，stderr 說明原因）
- 正例優先使用目標 skill 內現有的檔案；反例在暫存目錄臨時建立，驗收完刪除，不留在目標 skill 內
- 有落差時退回補正，不進入下一步

## Good Example

- 三項都實際執行過，結果符合預期

```text
--help                  → 退出碼 0
正例 errors.ok.md        → 退出碼 0，violations 為空
反例 errors.bad.md       → 退出碼 1，violations 指出 E1004 缺少重試建議
```

## Bad Example

- 只讀了原始碼就判斷沒問題，沒有實際執行

```text
讀過 scripts/check_error_codes.py，邏輯看起來正確 → 進入下一步
```

- 反例的退出碼是 0，腳本沒有檢查出預期的問題，卻直接進入下一步

```text
反例 errors.bad.md       → 退出碼 0，violations 為空
```
